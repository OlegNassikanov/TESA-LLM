# Обзор кодовой базы для новых участников

Этот репозиторий — ранний прототип **TESA-LLM**: протокола семантического представления, ориентированного на экономию токенов при работе с LLM.

## Структура репозитория

- `README.md`: концепция проекта, идеи и направления развития.
- `tesa.py`: основная Python-реализация словаря маркеров, сжатия/восстановления, бинарной сериализации и motif-логики.
- `tesa_motif.py`: на текущем этапе почти дубликат `tesa.py` (кандидат на рефакторинг).
- `tesa_packer.c`: нативная функция упаковки двух 14-битных маркеров в `uint32_t`.

## Ключевые компоненты

### 1) `TESACompressor`
Класс хранит:

- основной словарь маркеров (`S1`, `S2`, ...),
- временный словарь (`T1`, `T2`, ...),
- обратный индекс `phrase -> marker`,
- частоты фраз для простых эвристик.

Основные методы:

- `add_to_dictionary(phrase)` — добавляет или переиспользует маркер (включая fuzzy-сопоставление).
- `compress(text)` — токенизирует строку, кодирует маркеры в числа и применяет delta-кодирование.
- `decompress(compressed)` — восстанавливает абсолютную последовательность и маппит значения обратно в строки.
- `to_json(compressed)` — сериализация в JSON.
- `to_binary(compressed)` — бинарный пакет с `version`, `count`, payload и CRC16.
- `pack_markers(marker1, marker2)` — вызов C-функции упаковки через `ctypes`.

### 2) Motif-логика
В модуле есть минимальная модель «инструкция как музыкальный шаг»:

- `execute(action, duration)` — печать действия,
- `interpret_motif(motif)` — последовательный проход по шагам motif-структуры.

### 3) Нативная упаковка (`tesa_packer.c`)
Битовое представление пары маркеров:

`((uint32_t)s1 << 14) | (s2 & 0x3FFF)`

Это позволяет компактно хранить пару идентификаторов в одном 32-битном значении.

## Что важно знать перед началом

- Проект исследовательский: возможны дублирование кода и неустоявшиеся API.
- `tesa.py` и `tesa_motif.py` сейчас повторяют друг друга — это хороший первый пункт для рефакторинга.
- Python-код ожидает наличие `./tesa_packer.so` во время выполнения, но в репозитории хранится `tesa_packer.c`; нужно локально собирать `.so`.
- Для fuzzy-сопоставления требуется `fuzzywuzzy`.

## Пошаговый разбор Step 1 (на конкретном примере)

Пример входа:

`"hello world hello"`

### A) Что делает `add_to_dictionary` во время `compress`

После `split()` получаем слова: `['hello', 'world', 'hello']`.

1. `add_to_dictionary('hello')`
   - `frequency['hello'] = 1`
   - фраза новая -> назначается `S1`
2. `add_to_dictionary('world')`
   - `frequency['world'] = 1`
   - фраза новая -> назначается `S2`
3. `add_to_dictionary('hello')`
   - `frequency['hello'] = 2`
   - фраза уже есть -> переиспользуется `S1`

Последовательность маркеров: `['S1', 'S2', 'S1']`.

### B) Числовое кодирование маркеров

Для стабильных маркеров используется формула `id << 2`:

- `S1 -> 1 << 2 = 4`
- `S2 -> 2 << 2 = 8`
- `S1 -> 1 << 2 = 4`

До delta-кодирования: `[4, 8, 4]`.

### C) Delta-кодирование

- первый элемент сохраняется как есть: `4`
- второй: `8 - 4 = 4`
- третий: `4 - 8 = -4`

Результат `compress`: `[4, 4, -4]`.

### D) Восстановление в `decompress`

- старт: `4`
- следующий: `4 + 4 = 8`
- следующий: `8 + (-4) = 4`

Восстановленная абсолютная последовательность: `[4, 8, 4]`.

### E) Обратное декодирование маркеров

Для каждого `r`:

- `marker_type = r & 0b11`
- `marker_id = r >> 2`

Значит:

- `4` -> type `0`, id `1` -> `S1` -> `hello`
- `8` -> type `0`, id `2` -> `S2` -> `world`
- `4` -> type `0`, id `1` -> `S1` -> `hello`

Итог `decompress`: `"hello world hello"`.

Ключевая идея: младшие 2 бита несут тип маркера, старшие биты — идентификатор.
